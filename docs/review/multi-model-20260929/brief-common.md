# kakao-cs-jev 외부 공개 전 독립 리뷰 — 공통 지시

## 대상
- 저장소: 지금 작업 디렉터리(`{WT}`) — 커밋 `fd17c9f`(detached). 이 트리만 읽고 여기서만 실행한다.
- 무엇인가: 카카오톡 채널 1:1 문의를 카카오비즈니스 관리자 웹에서 Playwright로 읽어 Jev(TypeSafe 분류 API)로 분류하고, 확신 높은 건은 템플릿으로 자동 답장하고 나머지는 Discord 알림 + 상담 웹(Next.js, `web/`)의 사람 큐로 넘기는 봇. 봇(`src/`)과 web이 같은 postgres를 쓴다. 구조·실행 명령은 `CLAUDE.md`.
- **곧 외부에 공개한다.** 지금은 `127.0.0.1`에만 떠 있고, 공개하면 web이 Cloudflare Tunnel 뒤 공개 호스트명(`https://kakao-cs.<도메인>`)으로 인터넷에 열린다. 봇은 계속 내부에서만 돈다.
- **개인정보를 다룬다**: 고객 카카오 대화 원문·고객 이름(닉네임)이 DB에 저장되고, 마스킹한 문의가 제3자(Jev API)·Discord로 나간다. 상담원·관리자 계정이 web에 로그인한다.

## 규칙
- **독립 리뷰다.** `PLAN.md`, `PROGRESS.md`, `docs/review/` 아래 파일은 읽지 않는다(이전 리뷰 결과에 끌려가지 않게). `CLAUDE.md`·코드·테스트·`docs/superpowers/specs`·`docs/design`은 읽어도 된다.
- **코드를 고치지 않는다.** 산출물은 리포트 파일 하나(아래). 재현용 임시 스크립트는 `/tmp` 아래에만 두고, 추적 파일을 수정하지 않는다. 커밋하지 않는다.
- 금지: `~/.claude/` 아래 `*.env` 등 비밀 파일 읽기, `browser-data/`·`data/` 열람, 카카오 접속, **실제 Jev API 호출**(과금·원문 유출 — 필요하면 `web/test/harness.ts`의 `startStub()` 스텁), 실제 Discord 웹훅 호출, docker 컨테이너·tmux 세션 조작, 포트 3230·54329(떠 있는 데모 서버)와 3000 건드리기, `git worktree`·브랜치 조작.
- **다른 리뷰어 5명이 같은 머신에서 동시에 돈다.** 테스트·실기동은 하네스의 빈 포트 선택을 쓰고, 포트 충돌이 나면 다른 포트로 다시 한다. 무거운 작업(`next build`)은 필요할 때 한두 번만.
- 실행으로 확인할 수 있는 주장은 실행해서 확인한다(테스트 실행, 빌드된 standalone 서버 + embedded postgres로 실기동 프로브 등 — `web/test/harness.ts`의 `start()`를 `/tmp` 스크립트에서 import해 써도 된다). 확인 못 한 추정은 추정이라고 적는다.

## 리포트
- 파일: `{WT}/review-report.md` 하나. 한국어. 끝나면 마지막 메시지로 경로와 발견 수만 알린다.
- 맨 위: 리뷰어(모델명), 범위, 소요 시간, **외부 공개 판정**(공개 가능 / 조건부 — 먼저 닫을 것 목록 / 불가 — 사유).
- 발견마다: `### [심각도] 제목` — 심각도는 **치명**(공개하면 바로 악용·유출) / **주의**(공개 전 고칠 것) / **참고**. 위치(`파일:줄`), 구체 시나리오(누가·어떤 입력으로·무엇이 일어나는가), 근거(코드 인용 또는 실행 출력 — 실측인지 추정인지 명시), 고치는 방향 1~3줄.
- 마지막: **「확인했고 문제 아님」** — 점검했지만 결함이 아니었던 항목과 그 근거를 짧게. 오탐을 줄이는 데 쓰인다.
