
## 이번 패스: 보안·개인정보 평가
외부 공개 직전의 보안 리뷰다. 위협 주체별로 본다.
- **인터넷의 미인증 공격자**: 기본 거부 프록시(`web/proxy.ts`·`web/lib/public-paths.ts`) 우회(경로 정규화·대소문자·인코딩·`_next`·RSC·정적 파일·HEAD/OPTIONS), 로그인 리밋·계정 열거·타이밍, 세션 쿠키(봉인·만료·폐기), 오류 응답의 정보 노출, 보안 응답 헤더·`x-powered-by`, Cloudflare 뒤에서 `cf-connecting-ip`·`x-forwarded-*` 신뢰, 캐시(Cloudflare가 인증 페이지를 캐시할 수 있는가 — `Cache-Control`).
- **로그인한 상담원(agent)이 악의적일 때**: 권한 상승, admin API 접근, 다른 사람 문의 조작, 대량 열람·내보내기, CSRF(교차 사이트·같은 사이트 하위 도메인).
- **고객(카카오로 임의 메시지·닉네임을 보낼 수 있는 사람)**: 저장형 XSS(web 화면·Discord 알림·마크다운 링크·멘션), Jev 프롬프트 주입으로 분류를 조작해 자동응답·무음을 유도, 파서 혼란.
- **개인정보 흐름 전체**: 저장(평문·암호화 여부), 보존 익명화 범위와 빈틈, 마스킹(`src/mask.ts`) 우회 형식(직접 입력해 실측), 제3자 전송(Jev·Discord)에 원문이 섞이는 경로, 로그·스크린샷·HTML 덤프·백업·시드/데모 데이터, 퇴사자·비활성 계정의 접근.
- **배포·공급망**: 컨테이너 권한·네트워크 노출(포트 바인딩), 비밀값 취급, 의존성 취약점(`npm audit --omit=dev` — 배포본에서 도달 가능한지까지 판단).
- 가능한 한 실기동 프로브로 확인한다(빌드된 standalone + embedded pg, 쿠키를 직접 봉인해 역할별 요청 등).
