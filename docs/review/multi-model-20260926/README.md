## 읽기

- **다섯이 전부 잡은 것(A·B·C)은 원장에 이미 있는 「사람 판단 게이트」다.** 이번 리뷰가 그 판단을 재촉한다: A는 세션 해석 한 곳에서 DB `disabled`·`role` 재조회(또는 `sessions_valid_from` 열)로 닫히고, B는 IP 차원 또는 성공 시 미카운트로, C는 rooms·note 포함으로.
- **단독 발견 중 무게 있는 것**: J(opus-5.5 — 사람이 이미 답한 메시지에 자동응답, 코드로 확인됨: `newCustomerMsgs`가 `last_key`를 찾으면 그 뒤 `us` 메시지를 기준으로 삼지 않는다), K(astra — 무음 처리 확신도 하한), L(fable — 자리표시자 전송), F의 공백 2묶음(opus-5[1m])·전각 구분자(opus-5·5.5). 넷 다 자동 전송을 켜기 전(4단계)에 닫아야 한다.
- 모델 성향: astra는 발견 수는 적지만 주의 비중이 높고 빠르다(9분), 운영 판단 축(K)을 짚었다. opus-5.5는 처리 기준점 결함(J)처럼 상태 머신을 따라 읽는 발견이 있었다. fable은 확인 범위가 가장 넓고 참고 항목이 많다. opus-5 둘은 마스킹 실측 프로브가 가장 촘촘했다.
