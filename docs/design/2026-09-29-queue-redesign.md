# 상담 큐 리디자인 — 확정 (2026-09-29, 대화 세션·사용자 승인)

시각 보드: (비공개 아티팩트) · superdesign 프로젝트 `(비공개)`
시안의 고객명·건수·대화 문장은 예시다. 구현 때 실제 데이터·문구로 쓴다.

## 레이아웃
- **1280px 이상 — 3단**: 뷰 메뉴(전체·긴급·내 것·미배정 건수 + 카테고리별 건수) · 목록 · 상세(약 440px).
- **768~1279px — 2단**: 목록 400px(좁으면 340px) · 상세. 뷰 메뉴는 목록 위 필터 칩(전체/긴급/내 것/미배정) + 카테고리 아이콘 버튼.
- **768px 미만 — 1단**: 목록 → 상세 전체 화면(뒤로 「상담 큐」). 페이지 메뉴는 하단 탭 4개(상담 큐·처리 기록·통계·설정), 상담 큐 탭에 긴급 건수 배지.
- 폰의 누르는 곳(행·버튼·뒤로·카카오 링크) 44px 이상, 필터 칩은 40px. safe-area 여백. 폰 목록은 기본 선택 강조를 숨긴다(옆에 상세가 없다).

## 목록
- 섹션: 「긴급 · N」(빨간 글자) → 「새 문의 · N」 → 「내가 맡은 문의 · N」, 섹션 머리는 sticky.
- 행: (긴급이면 빨간 점) 고객명 · 경과 시간 / 문의 첫 줄(한 줄 말줄임) / 카테고리 라벨 + 확신도 미니 막대(40~48px) + %. 담당 표시는 맡은 문의에만(미배정은 표시 없음). 선택 행은 연파랑 바탕 + 왼쪽 accent 선.

## 상세 (위→아래)
1. 머리 한 줄: 고객명 · 상태 알약 · 담당 · 「카카오 방 열기」(노랑 점 표식)
2. 현재 문의: 연파랑 강조 상자 + 시각
3. 직전 대화: `inquiries.context`(최대 6줄), 화자 라벨 고객/상담원/자동응답 같은 폭, 마지막 상담원 답에 accent 왼쪽 선, 「더 보기」
4. 봇 판단: 상위 3개 카테고리 확률 막대(1위 accent, 나머지 회색) · 확신도 · 긴급(≥0.7 빨강) · 후속(≥followup_max면 「후속 질문」 주황 태그) · 봇 처리
5. 이 고객의 지난 문의 · N: 같은 room_id 과거 문의 — 날짜 · 카테고리 · 처리 결과 알약(자동응답/상담원 완료/무음), 펼치면 원문. (기간 단위 대화 대신 — 봇은 6줄만 저장하고 방을 다시 열면 읽음 처리된다)
6. 하단 고정: 분류 교정 select · 메모(접힘/아이콘) · 맡기(보조) · 완료(주)

## 시각 값
- 서체: Pretendard Variable만(자체 호스팅 그대로). 숫자 tabular-nums. `word-break: keep-all`.
- 색: bg #FFFFFF · surface #F6F7F9 · line #E6E8EC · fg #16181D · muted #6B7280 · accent #2563EB(하나) · danger #DC2626(긴급만) · success #16A34A · warning #D97706. 카카오 노랑 #FEE500은 「카카오 방」 링크의 점 표식에만.
- 다크(2026-09-29 사용자 요청, 기본은 시스템 설정): bg #111317 · surface #1A1D23 · line #2A2E36 · fg #E6E8EC · muted #9199A6 · accent #5B9CF8 · danger #F87171 · success #22C55E · warning #F59E0B. 채움(accent·danger) 위 글자는 다크에서 진한 남색(`--on-solid`). 값은 `web/app/globals.css` `:root`의 `light-dark()` 한 곳, 사용자 메뉴 「시스템·라이트·다크」가 쿠키 `theme` → `html[data-theme]`.
- 반경 6~8px(현재 문의 상자 12px), 그림자는 떠 있는 층에만. 그라데이션·보라·이모지 아이콘 금지.
